# Своя модель ассистента Sabyr (LoRA)

Ассистент ведёт короткий диалог на казахском или русском: один вопрос под схему, спокойное объяснение, без
давления. Здесь лежит всё, чтобы дообучить небольшую открытую модель на наших диалогах и подключить её к backend
как провайдер `own`.

| Файл | Что делает |
|---|---|
| `dialog_bank.py` | Вручную написанные реплики: 5 схем × kz/ru, подтверждение / отрицание / сомнение клиента |
| `build_dataset.py` | Собирает из них 1 600 диалогов (по 160 на пару «схема × язык», 2–4 реплики ассистента) |
| `checks.py` | Автопроверки реплик: язык, краткость, один вопрос, нет давления / жаргона / просьб о кодах; chrF |
| `finetune.py` | LoRA-дообучение (transformers + peft), потери только по репликам ассистента |
| `evaluate.py` | Оценка на отложенных диалогах: своя модель, внешний API или сами эталоны |
| `serve.py` | Сервер модели с OpenAI-совместимым `/v1/chat/completions` |
| `sample_dialogs.jsonl` | 10 примеров диалогов для быстрого просмотра |

Системный промпт строится общим кодом `sabyr_ml/assistant_prompt.py` — и в датасете, и в backend, — поэтому на
инференсе модель видит тот же формат, на котором училась.

## Запуск

Все команды — из каталога `ml/`. Нужен Python 3.11+, для обучения — GPU от 12 ГБ (T4 в Colab подходит).

```bash
pip install -e . && pip install -r llm/requirements.txt

# 1. Датасет: llm/data/{train,val,test}.jsonl
python -m llm.build_dataset

# 2. Дообучение. Адаптер сохраняется в llm/out/sabyr-assistant
python -m llm.finetune --base Qwen/Qwen2.5-1.5B-Instruct --epochs 3

# 3. Сервер модели
SABYR_ADAPTER_DIR=llm/out/sabyr-assistant uvicorn llm.serve:app --host 0.0.0.0 --port 8001

# 4. Оценка на отложенных диалогах -> docs/llm_eval_own.json
python -m llm.evaluate --target own --endpoint http://localhost:8001/v1
python -m llm.evaluate --target api      # для сравнения: внешний API, нужен ANTHROPIC_API_KEY
```

Подключение к backend — в `.env`:

```
LLM_PROVIDER=own
OWN_LLM_URL=http://llm:8001/v1
```

и `docker compose --profile own-llm up -d llm` (образ берёт адаптер из `ml/llm/out`).

### Проверка пайплайна без GPU и без скачивания весов

```bash
python -m llm.finetune --smoke --out /tmp/sabyr-smoke
```

Создаёт крошечную модель со случайными весами и токенизатор, обученный на самом датасете, и прогоняет те же
шаги: маскирование меток, LoRA, обучение, сохранение адаптера. Режим проверяет код, а не качество ответов.

## Выбор базовой модели

По умолчанию `Qwen/Qwen2.5-1.5B-Instruct`: открытая лицензия, умещается в 12 ГБ, знает русский и казахский.
Если есть GPU от 24 ГБ, для казахского стоит попробовать `issai/LLama-3.1-KazLLM-1.0-8B` (параметр `--base`).
Скрипту нужно лишь, чтобы у модели был chat-шаблон и слои `q_proj/k_proj/v_proj/o_proj`.

## Что оценивается

- доля реплик, прошедших все автопроверки (`all_checks_pass_rate`), и по каждой проверке отдельно;
- разрез по языку и по схеме;
- chrF к эталонной реплике (символьные n-граммы устойчивы к казахской морфологии).

Автопроверки не заменяют чтение диалогов носителем языка: перед боевым использованием выборку ответов модели
должен просмотреть человек.

## Состояние

Датасет, скрипты и сервер готовы и проверены в smoke-режиме (см. выше) и тестами `ml/tests/test_dialog_dataset.py`.
**Веса дообученной модели в репозитории нет**: в среде разработки не было GPU и доступа к Hugging Face.
До запуска шага 2 на машине с GPU провайдер `own` недоступен, и для демо используется `LLM_PROVIDER=api`.
