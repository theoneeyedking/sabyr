# Sabyr — мобильное приложение

Клиентская часть Sabyr: модуль мобильного банка, который срабатывает перед переводом и защищает клиента
от социальной инженерии. Приложение не блокирует перевод, а делает спокойную паузу: показывает риск,
причины, схему обмана, задаёт вопросы через помощника и при высоком риске зовёт доверенное лицо.

Стек: React Native + Expo SDK 58 (dev build, `expo-dev-client`), TypeScript, React Navigation
(native-stack), `react-native-web` для запуска в браузере. Интерфейс на казахском и русском.

## Быстрый старт (браузер)

```bash
cd mobile
npm install
EXPO_PUBLIC_API_URL=http://localhost:8001 npx expo start --web      # режим разработки
```

Статическая сборка (так приложение проверяется и показывается без телефона):

```bash
EXPO_PUBLIC_API_URL=http://localhost:8001 npx expo export --platform web   # результат в dist/
npx serve dist            # или любой другой статический сервер
```

Адрес API берётся из `EXPO_PUBLIC_API_URL` (значение вшивается при сборке). Если переменная не задана:
`http://10.0.2.2:8000` на эмуляторе Android и `http://localhost:8000` в браузере. Адрес можно поменять
на ходу в демо-меню — он сохраняется на устройстве.

## Android: dev build

Нужны Android Studio / Android SDK и JDK 17. В Expo Go приложение не запустится: в нём есть
собственный нативный модуль.

```bash
cd mobile
npm install
npx expo prebuild --platform android     # создаёт каталог android/ (в git не попадает)
npx expo run:android                     # сборка, установка на эмулятор/телефон и запуск Metro
# дальше достаточно: npx expo start --dev-client
```

Через EAS (облачная сборка, профиль `development` в `eas.json`):

```bash
npm install -g eas-cli
eas build --profile development --platform android
```

Что уже настроено в `app.json`:

- `expo-build-properties` → `usesCleartextTraffic: true`, чтобы работал `http://` адрес API;
- разрешение `READ_PHONE_STATE` (необязательное, запрашивается из демо-меню);
- пакет приложения `kz.sabyr.mobile`.

Для телефона в одной сети с компьютером укажите адрес компьютера:
`EXPO_PUBLIC_API_URL=http://192.168.x.x:8000` или впишите его в демо-меню.

## Нативный модуль `modules/sabyr-signals`

Локальный модуль на Expo Modules API (Kotlin), подключается автолинковкой — достаточно `expo prebuild`.
Проверить, что модуль найден: `npx expo-modules-autolinking resolve --platform android`.

| Что | Как определяется |
| --- | --- |
| `isCallActive()` | `AudioManager.getMode()` ∈ `MODE_IN_CALL`, `MODE_IN_COMMUNICATION`, `MODE_RINGTONE`. Разрешений не требует и ловит VoIP-звонки (WhatsApp, Telegram) — так обычно и звонят мошенники. Если выдано `READ_PHONE_STATE`, дополнительно учитывается `TelephonyManager` |
| `isScreenShared()` | `DisplayManager.getDisplays()` — есть включённый дисплей, кроме встроенного (виртуальный, презентационный, трансляция) |
| `getSignals()` | всё сразу + сырые данные для демо-меню: режим аудио, телефония, разрешение, имена дисплеев |
| событие `onSignalsChange` | слушатели `DisplayListener` и `OnModeChangedListener` (Android 12+) плюс опрос раз в секунду, пока есть подписчики |

Файлы:

- `android/src/main/java/expo/modules/sabyrsignals/SabyrSignalsModule.kt` — сам модуль;
- `index.ts`, `src/` — обёртка на TypeScript. На web и iOS нативного модуля нет: обёртка не падает,
  а возвращает `'unknown'`.

Ограничение, о котором стоит знать: Android не даёт стороннему приложению надёжно узнать о записи
экрана другим приложением. Виртуальный дисплей, созданный через MediaProjection без флага PUBLIC,
виден только его владельцу, поэтому `DisplayManager` уверенно ловит трансляцию на внешний экран
(Cast, Miracast, HDMI, DeX), а демонстрацию экрана внутри мессенджера может не заметить. Для демо
есть ручной переключатель.

В проверку перевода уходит

```json
{"signals": {"on_call": true, "screen_share": false, "session_seconds": 25, "source": "demo"}}
```

где `on_call` / `screen_share` = значение от устройства ИЛИ переключатель демо-меню; `session_seconds` —
секунды от входа (или возврата в приложение) до нажатия «Продолжить»; `source` = `demo`, если включён
переключатель или устройство ничего не сообщает (web/iOS), иначе `native`. Логика — в `src/lib/signals.ts`.

## Демо-меню

Открывается **пятью быстрыми нажатиями на логотип Sabyr** (или долгим нажатием) на экране входа
и на главной. В нём:

- переключатели «Идёт звонок» и «Демонстрация экрана»;
- быстрая подстановка счетов: дроп `KZ11SBA0000000007777`, друг `KZ22SBA0000000001111`
  (после нажатия открывается форма перевода с этим счётом);
- поле «Адрес API»;
- показания нативного модуля и то, что прямо сейчас уйдёт в `signals`.

## Сценарий показа

1. Войти как Гульнара Сейткали → демо-меню → включить «Идёт звонок» → «Счёт дропа».
2. Сумма 1 500 000 → «Продолжить». Экран Sabyr: риск > 70, три причины, схема, помощник,
   пауза 15 минут, запрос Данияру.
3. На втором устройстве (или в другой вкладке/окне инкогнито) войти как Данияр Сейткали →
   «Доверенное лицо» → «Отклонить».
4. Экран Гульнары в течение ~3 секунд сам переключается на «Перевод отклонён, деньги остались
   на вашем счёте».
5. Выключить «Идёт звонок», перевести 20 000 на счёт друга — обычное подтверждение без Sabyr.

Сбросить демо-данные: `cd backend && python manage.py seed_demo`.

## Проверки

```bash
npx tsc --noEmit        # типы
npx jest                # модульные тесты чистой логики (src/lib/__tests__)
```

Сквозной прогон в браузере (Playwright, мобильное окно 412×915) — `e2e/walkthrough.js`:

```bash
npx expo export --platform web
node e2e/walkthrough.js
```

Скрипт сам раздаёт `dist/`, проходит сценарий в двух окнах (Гульнара и Данияр) на живом API
и сохраняет скриншоты в `../docs/screenshots`. Настройки — переменными окружения:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `E2E_API_URL` | `http://localhost:8001` | адрес API |
| `E2E_APP_URL` | — | адрес уже запущенного приложения (тогда `dist/` не раздаётся) |
| `E2E_SHOTS` | `../docs/screenshots` | куда класть скриншоты |
| `E2E_MOCK_ASSISTANT` | `0` | `1` — подменять `/api/assistant/message` заглушкой (скриншоты чата тогда не показывают LLM) |

Нужен установленный Playwright с Chromium (`npm i -D playwright && npx playwright install chromium`,
если его нет в системе). Прогон меняет демо-данные (переводы, баланс) — после него удобно
выполнить `seed_demo`. Если сервис помощника не отвечает (404/5xx), прогон останавливается с ошибкой;
заглушка включается только явно.

## Структура

```
App.tsx                    навигация (стек экранов) и корневые провайдеры
src/api/                   клиент API и типы ответов
src/state/AppContext.tsx   сессия, язык, адрес API, сигналы устройства, демо-переключатели
src/i18n/                  тексты ru / kz
src/lib/                   чистая логика: деньги, таймер, сигналы, реестр (+ тесты)
src/components/            кнопки, шкала риска, чат помощника, итог перевода
src/screens/               Вход, Главная, Перевод, Подтверждение, Sabyr, Доверенное лицо, История, Демо-меню
modules/sabyr-signals/     нативный модуль Android (Kotlin) и обёртка на TypeScript
e2e/walkthrough.js         сквозной прогон демо-сценария
```

## Веб-версия на Vercel

Конфиг — [vercel.json](vercel.json): сборка `expo export --platform web`, раздаётся `dist/` (SPA).
Деплой: `cd mobile && npx vercel deploy --prod`. На Vercel едет только фронтенд: backend, PostgreSQL и Fabric
работают в Docker. Адрес API задаётся переменной `EXPO_PUBLIC_API_URL` при сборке или в «Демо-меню» приложения.
