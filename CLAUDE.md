# CLAUDE.md — Sabyr

Этот файл читает Claude Code в начале сессии. Здесь состояние проекта на 18 ноября 2026, правила работы и то, что осталось сделать.

## Что это

Sabyr — хакатонный проект (кейс Bank CenterCredit): защита клиента банка от социальной инженерии. Перед рискованным переводом приложение ставит паузу, показывает оценку риска и причины, подключает ИИ-помощника и доверенное лицо, а счёт мошенника помечается в межбанковском реестре.

- Сдача репозитория: **20 ноября 2026**. Живое демо в финале: **4 декабря 2026**.
- Основная ветка: `claude/sabyr-hackathon-mvp-e346tb`.
- Веб-версия приложения: https://sabyr-three.vercel.app (только фронтенд, см. «Vercel» ниже).

1. **Авторство коммитов — только владелец репозитория.** Перед первым коммитом выполни:
   ```bash
   git config user.name "theoneeyedking"
   git config user.email "202671635+theoneeyedking@users.noreply.github.com"
   ```

## Как запускать и проверять

Полный стенд требует Docker и Go: `cp .env.example .env`, вписать `LLM_API_KEY`, затем `make demo`. Чистый лист перед повторным показом — `make demo-reset`.

**В облачной сессии (например, с телефона) Docker и ключа, скорее всего, нет.** Там доступно только то, что не требует стенда:

```bash
cd mobile && npm install && npx tsc --noEmit && npx jest    # 32 теста
pip install -e ml && make test-ml                            # 37 тестов
make test-chaincode                                          # нужен Go
```

Тестам backend нужен PostgreSQL (`make test-backend`, 114 тестов). Если базы нет — скажи об этом прямо, не заявляй, что тесты прошли.

После изменения API перегенерируй `docs/openapi.yaml` командой `make openapi`, иначе упадёт тест схемы.

## Что уже сделано

- **Ассистент на настоящей LLM.** Слой `LLMProvider` в `backend/assistant/providers.py`: Anthropic по умолчанию, ключ из `LLM_API_KEY`, модель из `LLM_MODEL` (по умолчанию `claude-opus-5-5`). Таймаут 6 с × 2 попытки укладывается в 20-секундный таймаут приложения. При любой ошибке клиент получает заготовленный текст.
- **Причины риска формулирует LLM с проверкой** (`backend/assistant/reasons.py`). В модель уходят только шаблонные причины, схема, сумма и уровень. Текст принимается, только если совпали код причины, все числа и язык; иначе остаётся шаблон. У каждой причины в ответе API есть `source`: `llm`, `partial` или `template`.
- **Валидация** всех эндпоинтов: 400 вместо 500, `DJANGO_DEBUG=0` по умолчанию.
- **Шлюз реестра закрыт токеном** `LEDGER_GATEWAY_TOKEN`; обозреватель блоков открыт.
- **Новый дизайн приложения** (коммит «Новый дизайн приложения…»): тема в `mobile/src/theme.ts`, шрифт Onest, иконки в `components/Icon.tsx`, анимации в `components/Motion.tsx`, дуговая шкала риска в `components/RiskGauge.tsx`.
- **Защита ассистента от prompt injection** (`backend/assistant/guard.py`): подозрительная реплика клиента в LLM не уходит, небезопасный ответ модели заменяется согласованным текстом; в ответе API блок `guard`.
- **Граф без полного пересчёта:** отметка дропа сразу обновляет близость у соседей; `make refresh-graph` — пересчёт по расписанию.
- **«Сообщить о мошенничестве»** после отмены перевода: `POST /api/transfers/report`, блок на экране итога (`components/FinalState.tsx`).
- **Хэши реестра — HMAC-SHA256.** После обновления кода на стенде выполни `make demo-reset`, иначе старые отметки в реестре не совпадут с новыми хэшами.
- **Обзор рынка и позиционирование** — `docs/competitors.md`: что уже есть у Kaspi, НБ РК и других, чем Sabyr отличается, чего утверждать нельзя, ответы на трудные вопросы жюри. Читать перед правкой README и питча.
- **Проверено на живом стенде:** `demo_check.py` — все 5 шагов; e2e — 34 из 34; скриншоты 01–12 в `docs/screenshots/` сняты с настоящей LLM и новым дизайном.

## Vercel

- Проект `sabyr` в Vercel-аккаунте владельца, конфиг `mobile/vercel.json` (сборка `expo export --platform web`, раздаётся `dist/`).
- Деплой делается вручную с машины владельца: `cd mobile && npx vercel deploy --prod`. Проект не привязан к GitHub, поэтому пуш сайт не обновляет. Из облачной сессии деплой недоступен — просто скажи, что нужен ручной деплой.
- Адрес API задаётся переменной `EXPO_PUBLIC_API_URL` при сборке или в скрытом «Демо-меню» приложения (пять нажатий на логотип).

## На что не наступить

- **Дизайн.** Не задавай `fontWeight` — вес выбирается файлом шрифта через `fonts.*` из `theme.ts`. Все `testID` в экранах использует e2e-прогон, не переименовывай и не удаляй их.
- **Тексты интерфейса.** Ключи в `mobile/src/i18n/ru.ts` и `kz.ts` должны совпадать, тест это проверяет. Новый ключ добавляй в оба файла.
- **E2E.** `mobile/e2e/walkthrough.js` ожидает чистые данные: на «грязном» стенде падает шаг с доверенным лицом. Перед прогоном — `make demo-reset`. Заглушка помощника включается только явно: `E2E_MOCK_ASSISTANT=1`. Playwright в `package.json` не записан, ставится через `npm install --no-save playwright`.
- **Порты.** `API_PORT`, `DB_PORT`, `LEDGER_PORT` задаются в `.env`; на машине владельца стенд работает на 18000 / 15432 / 8090.
- **Модель LLM.** Не меняй модель по умолчанию без просьбы. Более быстрый и дешёвый вариант — `LLM_MODEL=claude-haiku-5-5`, выбор за владельцем.
